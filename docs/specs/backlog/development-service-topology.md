# 开发环境补齐 MCP 与 G2 SSR 服务

> 状态：Proposed
> 最后核对：2026-08-08
> 适用范围：`docker-compose.yml`、MCP 应用、`g2-ssr/` 服务与开发文档。

## 背景

当前 `docker compose up -d` 使用单个 `sqlbot` 容器启动 PostgreSQL、主 FastAPI 应用（8000）和 Vite（5173）。虽然 8001 已映射、`g2-ssr/` 已挂载，但默认命令未启动 `main:mcp_app` 或 G2 SSR 进程。

这会造成“仓库声明支持 MCP/服务端图表渲染”与“默认开发环境无法验证这些能力”的差距。

## 目标

- 为 MCP 和 G2 SSR 提供可重复、可观察的一键开发启动方式。
- 明确服务拓扑：独立 Compose service 或同容器受管进程，并记录端口、健康检查、日志和依赖关系。
- 更新 README、Quickstart、部署拓扑和运维手册，使“默认启动”与“可选启动”表述准确。

## 非目标

- 本待办不直接改变生产安装包或外部 MCP 客户端协议。
- 不在未核对生产启动方式、资源消耗和端口冲突前修改 `docker-compose.yml`。

## 验收标准

1. 新开发者执行文档中的命令后，可验证 MCP 服务和 G2 SSR 的可用性。
2. 服务失败时能通过明确的容器/进程日志定位。
3. 主 API、Vite、PostgreSQL、MCP 与 G2 SSR 的端口和启动状态在文档中一致。
4. 至少补充 MCP 连通性与图表 SSR 渲染的自动化或可重复人工验证步骤。

## 实施前需核对

- `main:mcp_app` 的启动命令、静态资源依赖和健康检查入口。
- `g2-ssr/` 的 Node 启动命令、依赖安装、端口和调用方。
- 生产 installer 是否已经启动这两个服务，以及开发/生产是否应保持相同拓扑。
