## 概述

SQLBot **没有传统的 RBAC（基于角色的访问控制）角色表**。权限体系是简洁的两层结构：

- **全局管理员**：硬编码判定，`sys_user.id = 1 AND sys_user.account = 'admin'`
- **工作空间级权限**：通过 `sys_user_ws.weight` 字段区分"工作空间管理员"和"普通成员"

全局管理员有且仅有一个——内置的 `admin` 用户。其他所有用户都是"子账户"，权限完全由工作空间成员关系（`sys_user_ws`）中的 `weight` 字段决定。

## 权限模型

### 三级权限一览

```
┌─────────────────────────────────────────────────────────────────┐
│                     全局管理员 (Admin)                           │
│   sys_user.id = 1 AND sys_user.account = 'admin'                │
│   - 所有系统功能                                                 │
│   - 所有工作空间                                                 │
│   - 绕过所有数据权限检查                                          │
│   - 唯一的全局管理员                                              │
└──────────────────────────┬──────────────────────────────────────┘
                           │
         ┌─────────────────┴─────────────────┐
         │                                   │
┌────────▼──────────────┐      ┌─────────────▼─────────────┐
│  工作空间管理员 (ws_admin) │      │     普通成员 (Member)       │
│  sys_user_ws.weight ≠ 0 │      │  sys_user_ws.weight = 0   │
│                         │      │                            │
│  ✅ 管理本空间成员         │      │  ✅ 使用数据源问答            │
│  ✅ 管理本空间变量         │      │  ✅ 创建/查看聊天             │
│  ✅ 管理本空间 AI 模型     │      │  ✅ 查看看板                  │
│  ✅ 管理本空间助手          │      │  ✅ 修改自己的密码            │
│  ✅ 管理行列数据权限       │      │  ❌ 所有管理功能              │
│  ✅ 使用数据源问答         │      │  ⚠️ 受行列数据权限限制         │
│  ✅ 创建/查看聊天          │      │                            │
│  ✅ 查看看板              │      │                            │
│  ❌ 全局用户管理           │      │                            │
│  ❌ 工作空间 CRUD          │      │                            │
│  ❌ 系统设置              │      │                            │
└────────────────────────┘      └──────────────────────────────┘
```

### Admin 判定逻辑

Admin 是**硬编码**的，不在数据库中存储。需要在 `id` 和 `account` 同时满足：

```python
# backend/apps/system/crud/user.py:32
userInfo.isAdmin = userInfo.id == 1 and userInfo.account == 'admin'
```

前端同样通过 ID 判定：

```typescript
// frontend/src/stores/user.ts:68
isAdmin(): boolean {
    return this.uid === '1'
}
```

**重要**：没有任何 UI 或 API 能将其他用户提升为全局管理员。

### Workspace Admin（工作空间管理员）判定

工作空间管理员的判定依赖 `sys_user_ws.weight` 字段：

```typescript
// frontend/src/stores/user.ts:77
isSpaceAdmin(): boolean {
    return this.uid === '1' || !!this.weight
}
```

- `weight = 0`：普通成员
- `weight ≠ 0`（通常是 1）：工作空间管理员
- 全局 Admin 也被视为所有空间的管理员

## 数据库表结构

### sys_user（用户表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInt (Snowflake) | 主键 |
| `account` | varchar(255) UNIQUE | 登录账号 |
| `name` | varchar(255) UNIQUE | 显示名称 |
| `password` | varchar(255) | MD5 加密密码 |
| `email` | varchar(255) | 邮箱 |
| `oid` | BigInt | 当前活跃工作空间 ID |
| `status` | int | 0=禁用, 1=启用 |
| `origin` | int (default 0) | 0=本地创建, 非0=外部平台同步 |
| `create_time` | BigInt | 创建时间（Unix 时间戳） |
| `language` | varchar(255) | 语言偏好 (zh-CN/zh-TW/en/ko-KR) |
| `system_variables` | JSONB | 用户级系统变量覆盖 |

**模型文件**：[backend/apps/system/models/user.py](backend/apps/system/models/user.py#L12-L30)

### sys_user_ws（用户-工作空间关联表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInt (Snowflake) | 主键 |
| `uid` | BigInt | 用户 ID（FK → sys_user.id） |
| `oid` | BigInt | 工作空间 ID（FK → sys_workspace.id） |
| `weight` | int (default 0) | **0=普通成员, 非0=工作空间管理员** |

**模型文件**：[backend/apps/system/models/system_model.py](backend/apps/system/models/system_model.py#L58-L65)

### sys_workspace（工作空间表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInt (Snowflake) | 主键 |
| `name` | varchar(255) | 空间名称 |
| `create_time` | BigInt | 创建时间 |

### sys_user_platform（外部平台用户关联表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInt (Snowflake) | 主键 |
| `uid` | BigInt | 用户 ID |
| `origin` | int | 平台类型 (1=CAS, 2=OIDC, 3=LDAP, 4=OAuth2, 6=WeCom, 7=DingTalk, 8=Lark) |
| `platform_uid` | varchar(255) | 外部平台用户 ID |

### 没有的角色表

SQLBot **没有**以下传统 RBAC 表：
- ❌ `sys_role`（角色表）
- ❌ `sys_role_permission`（角色-权限关联表）
- ❌ `sys_user_role`（用户-角色关联表）
- ❌ `sys_user` 中没有 `role` 列

## 权限检查流程

### 1. 认证中间件（TokenMiddleware）

**文件**：[backend/apps/system/middleware/auth.py](backend/apps/system/middleware/auth.py#L24-L229)

所有请求经过 `TokenMiddleware.dispatch()`，按优先级验证三种 Token：

| 优先级 | Token 类型 | Header | 用途 |
|--------|-----------|--------|------|
| 1 | Ask Token | `X-SQLBOT-ASK-TOKEN: sk ...` | API Key 访问 |
| 2 | Assistant Token | `X-SQLBOT-ASSISTANT-TOKEN: assistant ...` | 嵌入式助手 |
| 3 | 标准 Token | `X-SQLBOT-TOKEN: Bearer ...` | 用户会话（JWT） |

### 2. 端点级权限装饰器（require_permissions）

**文件**：[backend/apps/system/schemas/permission.py](backend/apps/system/schemas/permission.py#L49-L107)

```python
@require_permissions(permission=SqlbotPermission(role=['admin']))
# → 仅全局 Admin 可访问

@require_permissions(permission=SqlbotPermission(role=['ws_admin']))
# → 全局 Admin 或 工作空间管理员(weight≠0) 可访问
```

检查逻辑：

```
1. current_user.isAdmin AND permission.type 为空？
   → YES: 直接放行

2. role 包含 'admin'？
   → current_user.isAdmin 为 False → 拒绝

3. role 包含 'ws_admin'？
   → current_user.weight == 0 AND isAdmin 为 False → 拒绝

4. permission.type 存在？
   → 检查资源是否属于当前工作空间
```

### 3. 数据级权限（行列过滤）

**文件**：[backend/apps/datasource/crud/permission.py](backend/apps/datasource/crud/permission.py)

- **行权限**：为 SQL 查询注入 WHERE 条件，限制用户可见的数据行
- **列权限**：过滤结果集中的敏感字段
- **Admin 绕过**：`is_normal_user()` 对 admin 返回 False，admin 不受任何行列限制

### 4. 前端路由守卫

**文件**：[frontend/src/router/watch.ts](frontend/src/router/watch.ts)

- `/system/*` 路由：仅 `isAdmin` 用户可访问
- `/set/*` 路由：仅 `isAdmin` 或 `isSpaceAdmin` 用户可访问
- 数据源/助手管理路由：动态注册，基于权限判断

## 子账户（普通用户）创建指南

### 方式一：通过 UI 创建

1. 使用 **admin** 账号登录
2. 导航到 **系统管理 → 用户管理**
3. 点击 **「添加用户」** 按钮
4. 填写表单：

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | 名称 | 显示名称 | `测试用户A` |
   | 账号 | 登录账号（创建后不可修改） | `testuser` |
   | 邮箱 | 用户邮箱 | `test@example.com` |
   | 工作空间 | 可选择多个 | 勾选目标空间 |
   | 用户状态 | 开关，默认启用 | 启用 |

5. 点击 **「添加」**

> 默认密码为 `SQLBot@123456`（可在系统配置中修改 `DEFAULT_PWD`），创建后会显示在表单顶部。

6. 新用户以 **普通成员**（weight=0）身份加入所选工作空间

### 方式二：通过 API 创建

```bash
# 1. 获取 admin Token
curl -X POST http://<host>:<port>/api/login/access-token \
  -H "Content-Type: application/json" \
  -d '{"account":"admin","password":"<admin密码>"}'

# 响应示例：{"access_token": "eyJ..."}

# 2. 创建用户
curl -X POST http://<host>:<port>/api/user \
  -H "Content-Type: application/json" \
  -H "X-SQLBOT-TOKEN: Bearer <admin_token>" \
  -d '{
    "account": "testuser",
    "name": "测试用户",
    "email": "test@example.com",
    "oid_list": [1],
    "status": 1
  }'

# 响应中包含新用户的 id（例如 id=1234567890）
```

### 方式三：批量导入（Excel）

1. 进入 **系统管理 → 用户管理**
2. 下载 Excel 模板
3. 按模板填写用户信息
4. 上传 Excel 文件
5. 系统自动创建用户并关联工作空间

### 创建后的默认状态

| 属性 | 默认值 |
|------|--------|
| 工作空间角色 | `weight=0`（普通成员） |
| 活跃状态 | `status=1`（启用） |
| 密码 | `DEFAULT_PWD` 的 MD5 值（默认 `SQLBot@123456`） |
| 语言 | `zh-CN` |
| 来源 | `origin=0`（本地创建） |
| 活跃工作空间 | `oid_list` 中的第一个 |

### 将普通成员提升为工作空间管理员

目前 **UI 不支持**设置成员角色，需要通过 API：

```bash
# 将用户设为工作空间管理员
curl -X PUT http://<host>:<port>/api/system/workspace/uws \
  -H "Content-Type: application/json" \
  -H "X-SQLBOT-TOKEN: Bearer <admin_token>" \
  -d '{
    "uid": <用户ID>,
    "oid": <工作空间ID>,
    "weight": 1
  }'
```

> **注意**：只有全局 Admin 可以设置 `weight` 为非 0 值。工作空间管理员添加成员时 `weight` 固定为 0（参见 [workspace.py:133](backend/apps/system/api/workspace.py#L133)）。

## 权限隔离测试方案

### 测试环境准备

创建三个测试用户，覆盖所有权限级别：

| 用户 | 账号 | weight | 角色类型 |
|------|------|--------|---------|
| admin | `admin` | - | 全局管理员 |
| ws_admin_test | `ws_admin_test` | 1 | 工作空间管理员 |
| normal_test | `normal_test` | 0 | 普通成员 |

**快速创建脚本**（PowerShell）：

```powershell
# 配置
$BASE_URL = "http://localhost:8080/api"
$ADMIN_PWD = "SQLBot@123456"

# 1. 登录 admin
$loginResp = Invoke-RestMethod -Uri "$BASE_URL/login/access-token" `
  -Method Post `
  -ContentType "application/json" `
  -Body "{`"account`":`"admin`",`"password`":`"$ADMIN_PWD`"}"

$TOKEN = $loginResp.access_token
$HEADERS = @{ "X-SQLBOT-TOKEN" = "Bearer $TOKEN"; "Content-Type" = "application/json" }

# 2. 创建工作空间管理员
$wsAdmin = Invoke-RestMethod -Uri "$BASE_URL/user" -Method Post -Headers $HEADERS `
  -Body '{ "account":"ws_admin_test","name":"空间管理员测试","email":"wsadmin@test.com","oid_list":[1],"status":1 }'
Write-Host "ws_admin_test 已创建，ID: $($wsAdmin.id)"

# 3. 创建普通用户
$normal = Invoke-RestMethod -Uri "$BASE_URL/user" -Method Post -Headers $HEADERS `
  -Body '{ "account":"normal_test","name":"普通用户测试","email":"normal@test.com","oid_list":[1],"status":1 }'
Write-Host "normal_test 已创建，ID: $($normal.id)"

# 4. 将 ws_admin_test 提升为工作空间管理员
Invoke-RestMethod -Uri "$BASE_URL/system/workspace/uws" -Method Put -Headers $HEADERS `
  -Body "{`"uid`":$($wsAdmin.id),`"oid`":1,`"weight`":1}"
Write-Host "ws_admin_test 已设为工作空间管理员"

Write-Host "`n=== 测试用户创建完成 ==="
Write-Host "普通用户账号: normal_test"
Write-Host "空间管理员账号: ws_admin_test"
Write-Host "默认密码: SQLBot@123456"
```

### 验证方法

#### 1. 验证 UI 可见性

用不同用户登录，观察左侧导航菜单差异：

- **普通用户**：仅显示「工作台」相关菜单
- **工作空间管理员**：额外显示「设置」菜单（数据源管理、成员管理等）
- **全局管理员**：额外显示「系统管理」菜单

#### 2. 验证 API 拦截

```bash
# 获取普通用户 token
curl -X POST http://localhost:8080/api/login/access-token \
  -H "Content-Type: application/json" \
  -d '{"account":"normal_test","password":"SQLBot@123456"}'

# 尝试访问 admin 接口 → 应返回权限错误
curl http://localhost:8080/api/user/pager/1/10 \
  -H "X-SQLBOT-TOKEN: Bearer <normal_user_token>"
# 预期返回：403 或权限相关错误信息
```

#### 3. 验证数据隔离

1. 创建两个工作空间（WS_A, WS_B）
2. 用户 A 加入 WS_A，用户 B 加入 WS_B
3. 在 WS_A 中创建数据源和聊天
4. 用用户 B 登录，确认看不到 WS_A 的资源
5. 在数据源上配置行列权限规则，确认普通成员只能看到被授权的数据

## 常见问题

### Q: 能否创建第二个全局管理员？
**A:** 不能。全局管理员的判定是硬编码的 `id=1 AND account='admin'`，无法通过任何 UI 或 API 授予其他用户全局管理员权限。

### Q: 工作空间管理员能创建新用户吗？
**A:** 不能。创建用户的 API（`POST /api/user`）要求 `role=['admin']`，只有全局管理员可以创建用户。工作空间管理员只能将已有用户添加到自己的空间。

### Q: 一个用户可以属于多个工作空间吗？
**A:** 可以。用户在 `sys_user_ws` 表中可以有多条记录（多个 `oid`），用户可以在不同工作空间中拥有不同的 `weight`。

### Q: 如何重置子账户密码？
**A:** 管理员进入「用户管理」→ 点击用户行的锁图标 → 确认重置。密码会恢复为系统默认密码（`SQLBot@123456`）。或者通过 API：`PATCH /api/user/pwd/{id}`。

### Q: 外部平台用户能用本地密码登录吗？
**A:** 不能。`origin != 0` 的用户（来自 CAS/OIDC/LDAP/OAuth2/钉钉/企微/飞书）会被登录接口拦截，必须通过对应的平台认证登录。
